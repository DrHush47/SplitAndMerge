# Гейт: `code-gate` (точечный аудит скрипта правки / парсинга)

> **Назначение:** опциональная быстрая проверка нетривиального Python-скрипта до или после запуска (сложные правки таблиц `.docx`, массовая перенумерация, парсеры, правки в `pipeline/`). Для простых разовых скриптов (<100–150 строк без сложной логики) не требуется.
> **Активация:** вызывается как read-only саб-агент **только после подтверждения пользователя** (если среда поддерживает саб-агентов); иначе используется ведущим агентом как быстрый контрольный чек-лист.

---

## Бриф с фиксацией скоупа (Scope Pinning)

Заполняется перед запуском проверки:
- **SCRIPT_PATH (что проверяем):** `{{путь к workspace/<тема>/скрипты/<script>.py или diff в pipeline/}}`
- **TARGET_DATA (с какими файлами работает):** `{{путь к .docx / .pptx / targets.json}}`
- **РЕЖИМ:** строго **Read-Only** — код не переписывать, вернуть список конкретных рисков и точечных фиксов.

---

## Чек-лист проверки

1. **Среда и guardrails проекта (`AGENTS.md`):**
   - принудительный UTF-8 на `stdout`/`stderr` для Windows (`io.TextIOWrapper(..., encoding='utf-8', errors='replace')`);
   - запуск рассчитан на корневой `.venv`;
   - нет несанкционированного импорта/установки пакетов сверх установленного профиля `lite`;
   - **Session Workspace Containment (Принцип 8):** скрипт и все его выходные артефакты строго внутри `workspace/<тема>/` (не засоряют корень, `pipeline/` и `sandbox/`).
2. **Надёжность мутаций `.docx` (`hush-docx` R1–R4, [`../../docs/docx-protocol.md`](../../docs/docx-protocol.md)):**
   - **R1 (разведка):** структура документа не предполагается вслепую;
   - **R2 (якоря):** используются текстовые якоря / локаторы (`find_para(...)`, `pN`/`tN:rRcC`), а не жёсткие хрупкие индексы `doc.paragraphs[42]`;
   - **R3 (WARN, не exit):** некритичные несовпадения логируются через `WARN`, остановка только при риске потери данных;
   - **R4 (duplicate-check):** вставки защищены от повторного дублирования заголовков/абзацев;
   - проверены типовые ловушки: cross-run замены в ячейках таблиц (`replace_cross_run_in_cell`), операции «добавить + удалить» (риск оставить дубль), риск потери таблиц при ручных XML-мутациях, сохранение снапшота оригинала до перезаписи.
3. **Надёжность `.pptx` / сетевых скриптов (если применимо):**
   - для `.pptx`: используется `fit_in_box` (нулевая деформация пропорций), нет генерации картинок кодом, заполняются `notes_slide`;
   - для API/HTTP: выставлены таймауты, вежливые паузы (rate limits), нет синтетической генерации URL.
4. **Программный post-check:** предусмотрена ли верификация результата после сохранения (открытие файла, проверка метрик).

---

## Контракт ответа

1. **Итоговый статус:** `PASS` (безопасно запускать) или `FAIL` (есть риск потери данных / падения / нарушения guardrails).
2. **Список замечаний:** `Критичность (Блокер / Риск / Совет) | Строка | Проблема | Конкретный фикс`.
