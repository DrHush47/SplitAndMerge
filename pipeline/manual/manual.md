# Быстрый режим фактчекинга без зависимостей (Ур.1 → Ур.5)

> **Дополнительный режим**, не замена каскада. Основной путь — тяжёлый водопад
> Ур.0.5 → Ур.2 → Ур.3 из [`../docs/cascade.md`](../docs/cascade.md) — остаётся
> без изменений. Этот трек закрывает случаи, когда прогон Crawl4AI/Scrapling
> избыточен: схема каскада и словарь вердиктов НЕ расширяются.

## Идея

Формализация связки двух уже существующих уровней каскада:

1. **Ур.1 (researcher-web)** — агент веб-поиском собирает **кандидатов**-источников    по каждой цели из `targets.json` и выдаёт список ссылок.
2. **Ур.5-0 (человек, отбор)** — оператор вручную просматривает кандидатов,
   отбрасывает неподходящие и скачивает подходящее содержимое файлами в sources-dir.
3. **Агент (LLM) — основная сверка.** Оператор уведомляет агента об удачном
   скачивании источников; агент сам читает файлы из sources-dir и сверяет их с
   целями: проверяет DOI, авторов, год, ключевые утверждения по контексту
   (умное понимание текста вместо регулярок). Результат — evidence по каждой
   цели с цитатами, но НЕ финальные вердикты.
4. **Ур.5 (человек, вердикт)** — оператор просматривает evidence агента и
   выносит финальный вердикт по словарю каскада: `CONFIRMED` / `REFUTED` /
   `UNCERTAIN` / `BLOCKED`.

> **Агент и сканер НЕ выносят вердиктов.** Evidence-states
> (`RETRIEVED_OK` / `BLOCKED` / `FAILED` / `SKIPPED`) из `pipeline/verdicts.py`
> — не вердикты. НИКОГДА не превращать «есть файл с evidence» в `CONFIRMED` —
> подтверждение даёт человек (Ур.5) или программная проверка OpenAlex (Ур.0.5).

> **Почему агент, а не сканер.** Сканер `factcheck_manual.py` сверяет регекспами:
> берёт ПЕРВЫЙ DOI в тексте и побайтово сравнивает с DOI цели. На реальном
> md-дампе статьи это дало ложный MISMATCH (см. «Известный дефект» ниже) —
> первый найденный DOI был DOI цитируемой ссылки из списка литературы, а не DOI
> статьи. Агент понимает контекст и не фиксируется на шуме; сканер оставлен
> как опциональная техподдержка, не как шаг workflow.

## Когда применять

- Целей немного, а тяжёлый прогон каскада (браузеры, таймауты) избыточен.
- Сайты, которые проще скачать вручную из браузера, чем обходить скриптами.
- Агентский веб-поиск (Ур.1) уже собрал кандидатов — нужна их сверка агентом (LLM).

## Когда НЕ применять

- Много целей с DOI → сначала Ур.0.5 OpenAlex (`factcheck_openalex.py`): быстрее
  и даёт программный CONFIRMED/REFUTED.
- Нужен автоматический прогон всего каскада → `sam.py`.
- Страницы с anti-bot, недоступные для ручного скачивания → Ур.2/Ур.3/Ур.4.

## Workflow (типовой сеанс)

1. Заполните `pipeline/targets.json` (формат общий: `id` / `fact` / `url` / `expect`).
2. Попросите агента собрать кандидатов веб-поиском (Ур.1): по каждой цели —
   несколько ссылок с указанием, что там искать. Список кандидатов — **черновик,
   не подтверждение**.
3. Проверьте кандидатов в браузере и сохраните содержимое файлами в
   `workspace/manual/` (или собственный `--sources-dir`), соблюдая конвенцию имён
   (см. ниже). PDF сохраняйте как PDF, страницы — «Сохранить как» → HTML
   или скопируйте текст в `.txt`/`.md`.
4. **Уведомите агента** об удачном скачивании источников (например: «источники
   в `workspace/manual/`, проверь их по `workspace/targets_genome.json`). НЕ
   запускайте сканер — сверку делает агент чтением файлов (см. «Идея», шаг 3).
5. Агент вернёт evidence по каждой цели: найденные DOI, авторов, цитаты,
   оценку соответствия fact/expect, отметку о заглушках (Cloudflare и пр.).
   Файл-заглушку замените живым источником.
6. Вынесите вердикт по каждой цели по словарю `cascade.md` и запишите его
   в `results.md` (как в основном каскаде).

## Конвенция имён файлов

```
{id}[_\-. ]*.{txt|md|html|htm|pdf}
```

- `ref01_topol2019.pdf` → цель `ref01`
- `ref03.html`, `ref07-page.txt` — тоже валидно
- Несколько файлов на одну цель — ок (все попадут в отчёт `man_{id}.txt`).
- Файл, не совпавший ни с одним `id`, попадает в WARNING «orphan» в summary.
- Длинные `id` проверяются первыми: цель `ref1` не перехватывает файлы цели `ref10`.

## Технические константы

- **venv:** корневой (`.venv/Scripts/python.exe` на Windows, `.venv/bin/python`
  на Linux/Mac). НЕ искать python глобально.
- **Скрипт-раннер:** `pipeline/manual/factcheck_manual.py`
- **Запуск:**
  `.venv/Scripts/python.exe pipeline/manual/factcheck_manual.py --targets pipeline/targets.json`
- **Аргументы:** `--targets` (обязательный), `--sources-dir`
  (default: `<out-dir>/manual` = `workspace/manual`), `--prefix` (default: `man`),
  `--out-dir` (default: `<repo>/workspace`), `--window` (размер окна
  цитаты-контекста, симв., default: 300).
- **Выходные файлы:** `workspace/man_{id}.txt` — формат шапки совместим
  с остальными фактчекерами (URL/FACT/EXPECT/SUCCESS + секции по файлам).
- **Форматы:** `.txt`, `.md`, `.html`, `.htm` — stdlib; `.pdf` — опционально
  через `pypdf` (`pip install pypdf` в корневой venv). Без pypdf pdf-файлы
  помечаются `SKIPPED` с подсказкой, скрипт не падает.
- **Зависимости:** только стандартная библиотека (pypdf — опционально).
- **Коды выхода:** `0` — у каждой цели есть evidence (RETRIEVED_OK); `1` — есть
  цель без evidence (нет файлов / только BLOCKED/SKIPPED); `2` — ошибка
  конфигурации (targets не найден / пустой / неверный prefix).
- **Очистка:** после сеанса удалить `workspace/man_*.txt`; скачанные источники
  в `workspace/manual/` либо удалить, либо оставить для повторной сверки.

## Что проверяет сканер по каждому файлу

| Поле отчёта | Что означает |
|---|---|
| `STATE` | evidence-state: `RETRIEVED_OK` / `BLOCKED` / `FAILED` / `SKIPPED` (не вердикт!) |
| `EXTRACTOR` / `SIZE` | чем извлечён текст и размер файла |
| `SKIP` | причина пропуска: `pypdf-not-installed` / `unreadable` / `empty` / `unsupported` |
| `DOI` | `MATCH` / `MISMATCH (...)` / `not-found` — сверка DOI цели с DOI в тексте файла |
| `COVERAGE` | доля значимых слов из fact+expect, найденных в файле (стоп-слова — общий словарь `common.STOP_WORDS`) |
| `QUOTE` + `QUOTE-TERMS` | лучшее окно текста по покрытию терминами — готовая цитата для отчёта |

## Известный дефект сканера (2026-09-02)

`factcheck_manual.py` при сверке DOI использует `DOI_TEXT_RE.search(text)` —
первое совпадение регулярки `10\.\d{4,9}/\S+` по всему тексту, и побайтово
сравнивает его с DOI цели. На md-дампах статей это ненадёжно:

- **gen01** (Nature Communications, DOI `10.1038/s41467-018-04252-2`): первый
  DOI в тексте — `10.1126/science.aaf8729` из списка литературы статьи → ложный
  `MISMATCH`.
- **gen03** (PLOS Biology, DOI `10.1371/journal.pbio.3000224`): регулярка
  захватила якорь `#main-content` из md-ссылки → ложный `MISMATCH`
  (артефакт разметки, а не другой DOI).

Правильный DOI в обоих файлах присутствовал. Решение — сверка агентом (LLM),
который отличает DOI самой статьи от DOI в bibliography/якорях. Сканер не
исправлен и не удалён: используйте его поля STATE/COVERAGE/QUOTE как
вспомогательные, полю `DOI` доверять нельзя.
