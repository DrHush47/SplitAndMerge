# Sandbox — Полигон экспериментальной разработки и валидации новых возможностей

> **Назначение директории:**
> Изолированное исследовательское окружение (Feature & Capability Sandbox) для прототипирования, тестирования и сравнительного бенчмаркинга новых инструментов, библиотек, форматов документов и агентных скиллов до их стабилизации и интеграции в основной рабочий конвейер (`pipeline/`).

---

## Ключевые принципы организации

1. **Гарантированная изоляция (Non-Interference):**
   Любые скрипты, зависимости, временные файлы и генерации внутри `sandbox/` изолированы от production-кодовой базы и не влияют на стабильную работу основного пайплайна.
2. **Сравнительный бенчмаркинг (Evaluation & Quality Gate):**
   Новые подходы и скиллы проходят обязательную проверку на репрезентативных кейсах перед принятием решения об их внедрении:
   - оценка визуального и структурного качества;
   - устойчивость к ошибкам и скорость выполнения;
   - эргономика использования в многоагентном контуре.
3. **Чистота репозитория (Zero Clutter):**
   Все сгенерированные файлы (.pptx, .docx, изображения, логи и дампы) внутри `sandbox/` автоматически исключены из системы контроля версий Git через `.gitignore`. Сохраняются только описательные `README.md`.

## Регламент интеграции модулей в ядро и оформления коммита в Git

Когда функционал или инструмент в лаборатории `sandbox/` признан успешным и стабилизированным, агент или разработчик выполняет процедуру интеграции в ядро проекта и фиксации в репозитории по следующему протоколу:

### Шаг 1. Каноническая документация ядра
1. **Создать протокол модуля:** в `pipeline/docs/<модуль>-protocol.md` зафиксировать полный канонический регламент (роли, ограничения, алгоритмы, стандарты качества, чеклист Quality Gate).
2. **Обновить архитектуру:** в [`pipeline/docs/architecture.md`](../pipeline/docs/architecture.md) актуализировать обязанности соответствующей роли (напр., Роли 4 для генераторов или Роли 3 для текстовых блоков) и добавить ссылку на протокол.
3. **Обновить рабочий промпт роли:** в [`pipeline/prompts/<роль>.md`](../pipeline/prompts/) внести операционные инструкции для агента, входные данные, шаги сборки и список первоисточников.
4. **Обновить реестр констант:** в [`pipeline/docs/knowledge.md`](../pipeline/docs/knowledge.md) (§0.1) зафиксировать технические константы, библиотеки и команды.
5. **Обновить корневой README:** в [`README.md`](../README.md) добавить протокол в таблицу документации, дерево проекта (счётчик файлов docs), Карту чтения и инструкцию по установке/обновлению.

### Шаг 2. Фиксация зависимостей
1. Добавить стабильные версии библиотек в [`pipeline/requirements.txt`](../pipeline/requirements.txt).
2. Зарегистрировать именованную группу в [`pyproject.toml`](../pyproject.toml) в блоке `[project.optional-dependencies]`.

### Шаг 3. Фиксация статуса стенда и чистота репозитория
1. В таблице [`sandbox/README.md`](README.md) перевести статус стенда в `**Интегрирован в ядро**`.
2. В `sandbox/<стенд>/README.md` добавить раздел `## Статус интеграции` со ссылками на канонический протокол.
3. **Проверить `.gitignore`:** в Git должны попадать **только описательные `README.md`** из `sandbox/`. Любые бинарники (.pptx, .docx, изображения), `node_modules/`, кэши и тестовые дампы обязаны оставаться локальными.

### Шаг 4. Проверка целостности ядра (Quality Gate)
Перед формированием коммита обязательно убедиться:
1. Тестовый набор проходит без ошибок: `.venv\Scripts\pytest` (или `pytest`).
2. В `git status -u` отсутствуют лишние неотслеживаемые файлы, логи и временные скрипты.

### Шаг 5. Оформление коммита и запуск `sync.sh`
Коммит в Git — это не просто сохранение кода, а **точка входа для других пользователей и LLM-агентов**, открывающих проект в новой сессии:
* **Золотое правило сообщения коммита:** сообщение **ОБЯЗАНО явно указывать, что нужно докачать** для полного обновления локального окружения (`pip install -r pipeline/requirements.txt` или `pip install -e ".[...]"`) и какие модули были добавлены.
* **Формат вызова:**
  ```bash
  # Windows (через Git Bash):
  & "C:\Program Files\Git\bin\bash.exe" sync.sh "<модуль>: описание + зависимости (докачать: pip install -r pipeline/requirements.txt или pip install -e .[опции]) + затронутые протоколы"

  # Linux / macOS:
  bash sync.sh "<модуль>: описание + зависимости (докачать: pip install -r pipeline/requirements.txt или pip install -e .[опции]) + затронутые протоколы"
  ```
* **Контроль:** скрипт `sync.sh` автоматически проверит ветку `main`, выполнит `git add -A`, создаст коммит с датой и отправит изменения на remote `origin main`. По завершении зафиксируйте хеш коммита в отчёте.
